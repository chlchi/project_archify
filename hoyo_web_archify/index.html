HoYo Quest Voice 架构全景中枢

面向崩铁等游戏支线剧情的非侵入式 AI 实时配音系统。集成 Win32 DPI-aware 高清帧截取、8×32 灰度指纹门控（节省 80%+ 算力）、RapidOCR 文本识别、六级说话人路由与 GPT-SoVITS 异步流式语音合成。所有图表均支持节点检索、路径高亮、动态追踪、章节视角切换与高清导出。

01 · Architecture

系统总体分层架构图

展示游戏客户区 (HWND)、Win32 DPI 捕获、8×32 灰度指纹门控、RapidOCR 引擎、六级说话人路由、GPT-SoVITS 权重热切与 FastAPI 控制台的整体模块拓扑与信任域边界。

  • 包含 Windows 游戏客户区与 Python 核心调度双信任边界
  • 标注 Win32 API 原生无侵入抓取与 DPI 缩放解耦
  • 内置 3 套架构视角：核心流、门控流水线与容错自愈

02 · Workflow

端到端业务泳道工作流

基于 Schema v2 泳道模型呈现：游戏画面采集 → 打字机打字态等待 (CHANGING) → 文字稳定后触发 (STABLE_NEW) → 非对话场景短路 (UNSUPPORTED) → 别名纠错匹配与语音生成。

  • 明确划分抓取层、帧差门控层、OCR/路由层与 TTS 播放层
  • 三阶段设计：画面捕获、指纹比对门控、多级决策合成
  • 涵盖打字态去重、非对白场景短路与声音缓存复用

03 · Sequence

主循环 Tick 级交互时序图

呈现主轮询 Tick (15 Hz) 驱动捕获、指纹相似度计算门控、RapidOCR 区域文本推理、SpeakerRouter 六级决策、GPT-SoVITS /tts 权重切换与音频异步播报时序。

  • 覆盖 15Hz 主轮询 Tick 驱动与帧差短路时序
  • RapidOCR 区域文本提取与六级说话人路由决策时序
  • GPT-SoVITS 权重热切换与 Winsound 异步播放结算

04 · Dataflow

画面到音频数据流向图

5 阶段流式数据管道：HWND 显存缓冲区 → uint8 RGB 帧 → 降维 8×32 灰度特征与 ROI 裁切 → TextEvent 结构化文本与规范角色 ID → PCM/WAV 字节流与扬声器播放。

  • 从显存位图到 PCM 模拟音频的全形态递进映射
  • 8×32 灰度矩阵实现 1ms 级别超轻量指纹提取
  • 结构化 TextEvent 与遥测事件流多向解耦发布

05 · Lifecycle

帧差与任务状态生命周期

严格遵循 Archify 状态机轨道布局：主轨道（BOOTSTRAP → CHANGING → STABLE_NEW → SYNTHESIZING → PLAYING_DONE）与等待分支（UNCHANGED 免计算、CACHED_HIT 缓存复用）。

  • 主轨清晰展现正常对白处理的 5 阶段演进流转
  • UNCHANGED 状态直接短路，降低 80%+ 冗余开销
  • TTS 失败自愈重试与对白跳过 (SCENE_DROP) 终态收敛
